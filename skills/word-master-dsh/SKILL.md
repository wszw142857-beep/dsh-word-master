# Word Master（工具集版）

本 skill 是**精简入口**：讲清每一步调哪个工具、哪个关卡必须停下。

## 载荷根目录

```
${PAYLOAD_DIR}
```

上面是上游完整载荷（`word-master`）的绝对路径。下面提到 `references/...` 时，
用「根 + 相对路径」拼出绝对路径再读。

## 🚨 三条不可违反

1. **规格未冻结不写正文** —— 章节结构错了正文全废，而结构只在用户脑子里。
2. **P0 未清零不交付** —— `word_gate` 退出码 3 就是阻断，改到 0 或 4 再说。
3. **交付前必须真的看图** —— `word_render` 出 PNG 后逐页看过，不看退出码。

## 八步流水线

### ① 体检（`word_env`）

开工先调。缺 python-docx 就把补齐命令（工具已经给好了）交给用户；缺 LibreOffice
可以继续，但交付前要说明"未做渲染闸门"。

不要跳过这步去试错——直接 `word_build` 拿到 `ModuleNotFoundError` 只浪费一轮。

### ② 偏好核对（`word_pref`）

`action=read` 读当前偏好。用户在本次对话里提了新写作要求（"以后都用小四"
"别用'显著'这种词"）时，**先 `action=set` 落盘再开工**。

只在对话里答应是没用的：下一轮注入的还是旧偏好。

用户说"记住这个要求"时，除了 set，再用 `action=memory_text` 生成一段可写入
记忆空间的文字，让用户确认后存档。

### ③ 规格冻结（`word_spec`）— ⛔ 硬停

`action=init` 建草稿，补全 `sections`，然后**停下来问用户**：

- 标题、目标读者、文类（论文/报告/公文/说明书）
- 章节结构 ← 最常返工的一项
- 目标字数、语气

用户确认后才 `action=freeze`。

### ④ 逐节写正文

在 `<project>/draft.md` 里用 Markdown 写，**一次写一节**。

格式约定：
- `#` 文档主标题（通常由 spec 自动生成）
- `##` 一级章节，`###` 二级
- 段落之间空一行
- 表格用 `| a | b |`，第一行是表头
- 块级公式用 `$$...$$`，会转成 Word 原生可编辑公式

写的时候就要满足偏好：半角括号、不出现禁用词、每节首句"为了……"、方法章不写
具体数值。**这些第⑥步会逐条查。**

### ⑤ 构建（`word_build`）

Markdown → DOCX。版式从规格快照取，不用你操心。

### ⑥ 质检门（`word_gate`）— ⛔ 硬停

| 退出码 | 含义 | 动作 |
|---|---|---|
| 0 | 全过 | 进第 ⑦ 步 |
| 4 | 只有 P1 | 可交付，建议逐条处理 |
| 3 | 有 P0 | **不能交付**，改 draft.md 重建重跑 |
| 2 | 无法检查 | 看路径与文件是否存在 |

改的时候改 `draft.md` 再 `word_build` 重建，**不要手改 docx**。

### ⑦ 审阅界面（`word_review`）— ⛔ 硬停

`action=open` 起页面，**把返回的 URL 明确告诉用户**，然后等。

用户在页面上能：改字（写回 draft.md）、给段落提意见、写整篇意见、接受自动修复。

**交接判据**（二选一）：
- 用户说"好了/继续/可以了"
- `action=notes` 能看到新的意见

拿到信号后：
1. `action=stop` 关服务器（**必做**，别留僵尸进程）
2. 读 `review-notes.json` 和 `draft.md`，按意见改
3. 改完重新 `word_build` → `word_gate`

### ⑧ 渲染闸门 + 导出（`word_render` → `word_export`）

`word_render` 出 `render/pages/*.png`，**逐页看过**再宣布完成。

过了之后 `word_export`（要 PDF 就加 `pdf: true`）。

## 省 token 的操作纪律

1. **读文件用 `read` 工具，不要 `bash cat`** —— 前者有行号与 offset，能被压缩
   策略正确裁剪。
2. **每个参考文档只读一次** —— 需要时用 offset 分段，别反复回头读同一份。
3. **不要 `job_output` 长等** —— 后台任务用默认短超时轮询几次，先干别的。
4. **构建失败先看退出码** —— 缺模块是环境问题，路径错是参数问题，别不分青红皂白重试。
5. **不要为绕开报错手写脚本** —— 先看工具有没有覆盖（`extra_args` 透传未建模旗标）。

---

## 禁止事项

- ❌ 规格未冻结就写正文
- ❌ P0 未清零就调 `word_export`
- ❌ 只看 `word_render` 退出码就宣布完成
- ❌ 审阅界面用完不 stop
- ❌ 手改 docx 的 XML
- ❌ 把偏好当建议（它会被质检门真的查）
- ❌ 一次性吐完整篇（会前后风格漂移）

## 与 ppt-master 的对照

| | ppt-master | word-master |
|---|---|---|
| 中间产物 | 逐页手写 SVG | Markdown 稿 |
| 硬停点 | 八项确认 | 规格冻结 + 质检 P0 + 审阅 |
| 视觉闸门 | 渲染 PPTX 后拼总览图 | 渲染 PDF 后逐页 PNG |
| 审阅界面 | 选参数（风格/配色/字体） | **改正文 + 提意见 + 一键修复** |
| 记忆联动 | 无 | **偏好每轮注入系统提示词** |

最后一行是关键：PPT 的偏好（风格、配色）可以在确认环节当场问；写作偏好是长期
约束，必须每轮在场，不能靠模型想起来。
