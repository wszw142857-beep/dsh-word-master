# Word Master 流程详解

本文件是 `word-master` skill 的详细流程规范。SKILL.md 讲纪律，这里讲每一步
具体做什么、判据是什么、哪里最容易返工。

## 全景

```
素材/需求
   ↓ ①体检
环境就绪？
   ↓ ②偏好
偏好已核对？
   ↓ ③规格冻结 ← 硬停（问用户）
spec.json (frozen)
   ↓ ④逐节写
draft.md
   ↓ ⑤构建
output.docx
   ↓ ⑥质检门 ← 硬停（P0 阻断）
gate-report.json
   ↓ ⑦渲染闸门 ← 必须看图
render/pages/*.png
   ↓ ⑧导出
final.docx / final.pdf
```

---

## ① 体检（word_env）

判据：解释器可用 + `docx` / `lxml` 已装。

常见失败与处置：

| 症状 | 原因 | 处置 |
|---|---|---|
| 找不到解释器 | Python 未装或 PATH 缺失 | 装 Python 3.10+，或设 `DSH_WORD_PYTHON` |
| 解释器返回 49 | 命中 WindowsApps 商店别名 | 换真实解释器或设 `DSH_WORD_PYTHON` |
| 缺 `docx` | 没装 python-docx | `pip install python-docx lxml` |
| 缺 LibreOffice | 未装或不在默认路径 | 装 LibreOffice，或设 `DSH_WORD_SOFFICE` |

---

## ② 偏好核对（word_pref）

偏好有两层用途：

1. **约束**：质检门会真的按它查（全角括号、禁用词）；
2. **注入**：每轮进系统提示词，模型写的时候就看得见。

所以用户提新要求时**必须落盘**，只在对话里答应是没用的 —— 下一轮注入的还是旧
偏好。

补丁格式与偏好文件同构，只写要改的键：

```json
{ "formatting": { "bodySizePt": 10.5, "lineSpacing": 1.25 } }
```

设 `null` 表示显式关闭某项，例如关掉节首句检查：

```json
{ "sectionOpener": { "enabled": null } }
```

## ③ 规格冻结（word_spec）— 硬停

### 必须问用户的四项

| 项 | 为什么必须问 |
|---|---|
| 章节结构 | 最常返工的一项。模型猜出来的结构和用户脑子里的一定不一样 |
| 目标读者 | 决定术语密度与解释深度 |
| 文类 | 论文/报告/公文/说明书的版式与语气差异很大 |
| 目标字数 | 决定每节展开到什么程度 |

### 冻结时发生了什么

- `frozen: true` + `frozenAt` 时间戳
- **偏好快照**：把当时的偏好整份存进 spec
- **版式快照**：从偏好里取出版式存进 spec

快照的意义：用户之后改了偏好，已冻结的项目**不受影响**。构建时优先读快照，
读不到才读当前偏好。

---

## ④ 逐节写正文

### 为什么一节一节写

一次性吐完整篇有三个问题：前后风格漂移、某节写崩了要全部重来、用户想调整
结构时代价最大。逐节写让每次返工只影响一节。

### Markdown 支持的子集

| 写法 | 效果 |
|---|---|
| `## 标题` | 一级章节（Word Heading 1 样式） |
| `### 标题` | 二级 |
| 普通段落 | 首行缩进、两端对齐、按偏好行距 |
| `- 项` | 无序列表 |
| `1. 项` | 有序列表 |
| `> 引用` | 缩进块 |
| `\| a \| b \|` | 三线表（首行表头） |
| `**粗体**` `*斜体*` | 行内格式 |

**不支持**：嵌套超过两层的列表、脚注、内嵌图片（图片走单独配置，见下）。

### 写的时候要同时满足的约束

这些都会被第 ⑥ 步真的查：

- 全文半角括号 `()`
- 不出现四类禁用词（防御性/交付性/元表述/过程性）
- 每节首句"为了 + 问题，需要 + 动作"（方法章除外）
- 方法章不出现具体数值（公式常数、术语内数字、引用年份、表图号除外）
- 标题不跳级（`##` 之后不能直接 `####`）

## ⑤ 构建（word_build）

脚本做三件事：解析 Markdown → 套版式 → 写 docx。

版式来源优先级：spec 的 `formattingSnapshot` → 当前偏好 → 内置默认。

**构建不等于排版完成**。字体回退、表格线错位这类问题构建阶段看不出来，要靠
第 ⑦ 步。

---

## ⑥ 质检门（word_gate）— 硬停

### 判据表

| 检查项 | 严重度 | 判据 |
|---|---|---|
| 全角括号 | P0 | 数量必须为 0 |
| 禁用词 | P0 | 各类命中数必须为 0 |
| 缺章节 | P0 | 规格列出的章节都出现 |
| 标题缺失 | P0 | 开头出现规格标题 |
| 标题跳级 | P0 | 层级不跳（1→3 算跳） |
| 节首句 | P1 | 符合"为了……"句式（方法章豁免） |
| 方法章数值 | P1 | 无裸数字（白名单外） |

### 退出码

| 码 | 含义 | 动作 |
|---|---|---|
| 0 | 全过 | 进第 ⑦ 步 |
| 4 | 只有 P1 | 可交付，建议处理 |
| 3 | 有 P0 | **阻断**，改 draft.md 重建重跑 |
| 2 | 无法检查 | 检查路径与文件是否存在 |

### 改的方式

**改 `draft.md` 再重建，不要手改 docx。** 手改的 docx 会在下次重建时被覆盖，
而且破坏三线表的边框结构。

---

## ⑦ 渲染闸门（word_render）— 必须看图

### 流水线

```
output.docx --(LibreOffice)--> output.pdf --(PyMuPDF)--> pages/page-01.png ...
```

### 看图要看什么

| 症状 | 看起来是什么 | 原因 |
|---|---|---|
| 字体回退 | 中文变成方框或宋体以外的字 | 字体名不在系统里，或 `w:eastAsia` 没设 |
| 表格错位 | 列宽挤压、文字换行奇怪 | 列宽未按内容分配 |
| 标题孤行 | 标题在页尾，正文在下一页 | 缺少 keep-with-next |
| 中英混排挤压 | 英文贴住中文 | 未设置中西文间距 |

**退出码只能告诉你"渲染成功"，不能告诉你"看起来对不对"。** 必须真的打开图看。

### LibreOffice 缺失时

脚本会跳过并在报告里说明。此时**不能宣布"已通过视觉验收"**，只能说"结构质检
通过，未做视觉验收"。

---

## ⑧ 导出（word_export）

三件事：

1. 补核心属性（标题、作者、语言），避免文档属性一片空白；
2. 回读校验：重新打开产物，确认 zip 结构完好、段落数非零；
3. 可选转 PDF（与渲染闸门同一套引擎）。

---

## 常见返工点

| 现象 | 根因 | 改法 |
|---|---|---|
| 质检一直 P0 全角括号 | 模型按中文习惯打 `（）` | 全文替换成 `()`，表头也要换 |
| 节首句一直 P1 | 写了"本节讨论……" | 改成"为了……，需要……" |
| 方法章一直 P1 | 写了具体浓度/深度 | 移到结果章，方法章只留公式与术语 |
| 构建出来字体不对 | 系统没有该字体 | 改偏好里的字体名，或装字体 |
| 表格线没出来 | 用了模板自带的表样式 | 三线表由脚本画，别在 Markdown 里期待样式 |
